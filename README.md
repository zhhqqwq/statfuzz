# StatFuzz

**English** | [简体中文](README.zh-CN.md)

**Property-based stress testing and automatic counterexample discovery for statistical methods.**

StatFuzz asks a different question from a typical statistics library:

> Instead of only computing a statistical method, can we automatically discover the data-generating conditions under which its advertised finite-sample behavior starts to break down?

## v0.1 scope

The first release is intentionally narrow. It estimates the empirical Type-I error of the two-sided Welch t-test under controlled data-generating processes (DGPs).

Built-in DGPs:

- Normal
- shifted LogNormal
- Student-t
- two-component Normal mixture

The architecture is designed so later releases can add confidence-interval coverage, bias, power, calibration, automatic parameter search, counterexample shrinking, and reproducible reports without changing the basic user model.

## Quick start

```bash
pip install -e .
```

```python
from statfuzz import stress_test
from statfuzz.dgp import LogNormal

result = stress_test(
    method="welch_ttest",
    metric="type1_error",
    dgp=LogNormal(sigma=1.4),
    n1=12,
    n2=12,
    simulations=10_000,
    alpha=0.05,
    seed=42,
)

print(result)
```

Example output:

```text

Metric:              type1_error
...
Nominal alpha:       0.0500
Empirical alpha:     ...
Monte Carlo SE:      ...
Status:              ...
```

The numerical values are generated by simulation; they are not hard-coded claims about Welch's test.


## Grid search

StatFuzz can also enumerate a finite, reproducible parameter space while keeping the search layer independent from any particular DGP:

```python
from statfuzz import stress_test
from statfuzz.dgp import LogNormal
from statfuzz.search import ParameterSpace, grid_search

space = ParameterSpace({"n": [8, 12, 20], "sigma": [0.6, 1.0, 1.4]})

def evaluate(point, seed):
    return stress_test(
        method="welch_ttest",
        metric="type1_error",
        dgp=LogNormal(sigma=point["sigma"]),
        n1=point["n"],
        n2=point["n"],
        simulations=2_000,
        seed=seed,
    )

search = grid_search(space=space, evaluate=evaluate, seed=42)
print(search.to_markdown())
```

The result retains every evaluated point. Ranking by absolute deviation is explicitly exploratory; a selected candidate should be re-simulated with an independent validation budget before being presented as a confirmed counterexample. See `docs/SEARCH.md`.


### Independent candidate validation

```python
from statfuzz.search import validate_candidate

validated = validate_candidate(
    search=search,
    evaluate=validation_evaluate,
    validation_root_seed=2026,
)
```

The selected ParameterPoint is re-simulated with a new deterministic random stream. Search and validation estimates, seeds, MCSEs, and simulation budgets remain separate in the returned result object.


### High-level discovery

```python
from statfuzz.search import find_counterexample

discovery = find_counterexample(
    space=space,
    search_evaluate=search_evaluate,
    validation_evaluate=validation_evaluate,
    search_root_seed=42,
    validation_root_seed=2026,
)
```

This composes grid search, top-candidate selection, and independent validation while retaining the full search table. The returned object represents a validated simulation candidate within the searched DGP family; it is not a mathematical proof of a universal counterexample.

## Statistical contract

For a Type-I error experiment, the two DGPs must satisfy the null hypothesis being evaluated. In v0.1 this means equal population means. Built-in skewed and mixture generators therefore expose explicit arithmetic-mean controls.

The Monte Carlo standard error is reported as

\[
\operatorname{MCSE}(\hat p) = \sqrt{\frac{\hat p(1-\hat p)}{B}},
\]

where \(B\) is the number of simulation replicates.

A result is marked `OUTSIDE_TOLERANCE` when

\[
|\hat p - \alpha| > \text{tolerance}.
\]

That label is a user-defined engineering criterion, not a formal hypothesis test.

## Design

```text
DataGenerator
     |
     v
Monte Carlo Simulation
     |
     v
Statistical Method
     |
     v
Property / Metric
     |
     v
StressTestResult
```

v0.1 keeps the public API small while separating DGPs, methods, metrics, and simulation orchestration internally.
